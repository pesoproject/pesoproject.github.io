The problem space

Familiar failure modes

Every team building on scientific software hits the same wall eventually. PESO exists to move that wall.

$ diagnose --common-issues
  • Installing 3rd-party libs breaks on dependency mismatches
  • Version updates introduce breaking changes downstream
  • New tools disrupt existing team workflows
  • Portability across CPU/GPU is manually managed
  • Build times balloon as projects grow
  • Algorithms fall out of date, hurting perf and security
$ resolve --with-peso
  • Curated, tested library portfolio via Spack + E4S
  • Coordinated release and compatibility testing
  • User- and developer-experience research baked in
  • Community engagement as a first-order priority
  • Direct line to CASS community expertise
  • Shared investment across DOE, vendors, and academia
Program structure

Six thrusts, one ecosystem

Parallel work areas, each shipping into the same shared stack.

Software Ecosystem Integration
